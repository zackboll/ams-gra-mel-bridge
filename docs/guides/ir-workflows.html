IR Workflows

Complete compiled and executed programs are in the Examples guide, including owned images, pixel leases, common requests, navigation submission and mixed metadata.

IR is Session-backed and channel-oriented. Open a Session with {{package:AMS.MEL}}, then configure the particular channel family. Provider library and configuration values are deployment inputs, not portable examples.

Discover before choosing an attachment

AMS.MEL.IR.Discovery.Capabilities in {{package:AMS.MEL.IR.Discovery}} returns the complete advertised capability list in provider order. The result and its nested values are Ada-owned snapshots; an empty list is valid. Use the advertised identities to choose an attachment. Zero image dimensions or sizes remain zero and can describe an unconfigured sensor. Advertisement neither configures acquisition nor proves that a later attachment or optional operation will succeed. Serialize discovery against Session closure and other provider operations.

Image stream: attach, start, consume, close

{{package:AMS.MEL.IR}} supplies Create_UCI_ID, Create_Component_Location, Create_Image_Config, Open_Image_Stream, Start, Stop and Close. Configuration owns the identities, sensor location and positive buffer/queue bounds. Opening attaches but does not start reception.

Illustrative operation sequence, not standalone executable Ada: the caller supplies valid provider configuration, identities, mounting values, and exception handling.

Image commands and metadata without acquisition

Use Create_Image_Control_Config and Open_Image_Control in AMS.MEL.IR when the application needs Image commands, capabilities, common services or metadata without image buffers. This path returns the same limited Image_Stream owner and accepts an advertised layout whose acquisition fields are zero. It supports Image.Submit_Navigation_Report, Image.Capabilities, Image.As_Channel and the eligible metadata operations through their existing contracts.

On this attachment, Start enables the channel without allocating or registering image buffers. Both image Receive paths and Acquire_Frame raise Provider_Error with a control-only diagnostic; enabling does not turn the owner into an acquisition stream. Submission while attached does not require Start where the operation's contract permits it. Provider rejection remains a normal result when that API returns a rejection discriminator.

Full representation is not a new format negotiation path

The legacy AMS.MEL.IR.Receive returns a source-compatible Mono8 frame subset. {{package:AMS.MEL.IR.Image}} provides the complete published FrameHeader representation in Full_Frame, preserving nested metadata and pixels as an independent Ada copy. Both use the current validated Mono8 single-band stream path; a complete header representation is not support for every upstream pixel format.

Acquire_Frame returns a limited Frame_Lease with small metadata copied into Ada and a retained provider payload. With_Pixels borrows only during its processor invocation; Copy_Pixels produces independent Ada storage. Do not retain a view beyond the invocation or race Close with a borrow. Lease Close invalidates the payload and resets its count; copied metadata remains. Buffer-release failure reports an error and conservatively retains uncertain storage, not successful release. Only one Receive/Acquire consumer may operate on a stream at a time.

Capabilities and commands

{{package:AMS.MEL.IR.Channel}} defines common identities, pixel vocabulary and complete capability snapshots. AMS.MEL.IR.Image.Capabilities and AMS.MEL.IR.C2.Common.Capabilities return Ada-owned values. An enum member such as an optional metadata kind is not evidence that its callback is implemented or that the provider supplies it.

{{package:AMS.MEL.IR.C2}} owns Control_Channel: configure, Open, explicitly Enable, then submit commands such as Submit_Mode, Submit_BIT_No_Op or Submit_Config_Set. ModeCmd preserves complete ScanParam; supported BIT operations are the documented one-choice operations, not arbitrary invented payloads. {{package:AMS.MEL.IR.C2.Common}} provides pre-enable KeepAlive, asynchronous CommsTest and capability inspection.

Additional C2 operations use the values and results in {{package:AMS.MEL.IR.Camera}}, {{package:AMS.MEL.IR.Camera_Protection}}, {{package:AMS.MEL.IR.Calibration_Configuration}}, {{package:AMS.MEL.IR.Calibration_Status}} and {{package:AMS.MEL.IR.Erase}}. Camera control and protection are conditional on the corresponding provider support; calibration and erase operations are optional. Camera commands also have an Image submission path. The C2-specific {{package:AMS.MEL.IR.C2.System_Data}} sends the canonical Track.System_Data.System_Track_Data_Response value using the C2 lifecycle. Check each submission's required channel state and its result before reading success or rejection details; a successful asynchronous result does not establish physical camera action, erasure or incorporation of track data.

Bounded metadata delivery

{{package:AMS.MEL.IR.C2.Metadata}} receives CommandStatus, BIT_Configuration and BIT_Status, with explicit ChannelCommsTest admission. {{package:AMS.MEL.IR.Image.Metadata}} receives BadPixelList, LineOfSightReport, LineOfSightEuler and NavigationReportResp through its base metadata stream. Independent opt-in Image owners receive NUC/temperature, CameraResponse, OpticalDistortionMap and LineOfSightQuaternion. Their values live in {{package:AMS.MEL.IR.NUC}}, AMS.MEL.IR.Camera, {{package:AMS.MEL.IR.Optical_Distortion_Map}} and {{package:AMS.MEL.IR.Line_Of_Sight_Quaternion}}. Opening the base metadata stream does not register these additional callbacks. C2 similarly has separate opt-in CameraProtection, CalibrationConfiguration and CalibrationStatus streams.

Native provider callbacks enqueue; Ada consumers use Receive in C2.Metadata, Image.Metadata, Health_Status.Metadata and Instrumentation.Metadata to obtain copied values. Track.Metadata.Receive_Event returns tagged multi-kind events; its separate Receive convenience function returns Track reports only. If that convenience function consumes a non-report event, it raises Provider_Error rather than skipping or requeuing it. Use Receive_Event for mixed Track metadata kinds. Queues are bounded, drop incoming events when full, and expose counters; they are not lossless buses.

Common communications-test metadata

For Health, Image and StackedImage, obtain the typed owner's As_Channel view, then explicitly call {{package:AMS.MEL.IR.Channel.Metadata}} Open. Registration is one-shot per typed channel, including failed attempts and attempts through different views. A control-only Image attachment is eligible. C2 retains C2.Metadata.Enable_Comms_Test_Events and its existing mixed queue; the common metadata Open is not an alternative C2 registration path.

Receive returns an owned command/request identifier pair from the bounded FIFO. A callback and a CommsTest request's future are independent observations; neither completes or substitutes for the other. Queued reports drain after typed channel closure before the stopped/error outcome. Closing the metadata stream deactivates consumption without unregistering the callback or closing the typed channel. These metadata owners and common views do not keep the typed owner alive.

Health, Instrumentation and Track

{{package:AMS.MEL.IR.Health_Status}} owns its channel and {{package:AMS.MEL.IR.Health_Status.Metadata}} delivers copied status metadata. Its Status alias targets {{package:AMS.MEL.Status}}; the known GNATdoc package-renaming omission does not mean status support is missing.

{{package:AMS.MEL.IR.Instrumentation}} is conditional: configure, Open, Enable, Submit, Wait and Close. {{package:AMS.MEL.IR.Instrumentation.Metadata}} receives InstrumentationReport. {{package:AMS.MEL.IR.Track}} is likewise conditional. {{package:AMS.MEL.IR.Track.Updates}} submits TrackDataUpdate; {{package:AMS.MEL.IR.Track.System_Data}} submits SystemTrackDataResponse. {{package:AMS.MEL.IR.Track.Metadata}} delivers IRSTTrackReport, RequestSystemTrackData, CandidateObjectMessage and CandidateObjectPreProcMessage on one FIFO queue. Those inbound callbacks have no corresponding upstream send overload. Positive Track behavior is mock-backed; the pinned Squall observation is a clean failure to attach a Track channel, not positive Track execution.

Scheduling and StackedImage foundations

{{package:AMS.MEL.IR.Scheduling}} supports configuration, Open, explicit Enable, copied Capabilities, a weak As_Channel view and Close when the provider publishes the Scheduling category. A zero Task_Schedule_Depth is a valid application-managed mode. {{package:AMS.MEL.IR.Scheduling.Metadata}} independently registers and receives ExecuteTaskAck and TaskExecutingRep. An acknowledgement is not task completion; a report describes what the provider says is executing. Scheduling task exec overloads, PrioritizedTrackListCmd send and the remaining Scheduling callbacks are unbound.

{{package:AMS.MEL.IR.Stacked_Image}} provides attachment, Enable, Capabilities, a weak common view and Close. Common communications-test metadata is available through Channel.Metadata. This foundation creates no acquisition buffers or stack listeners and supplies no stack reception. Generic buffer registration and optional LOS3D reception remain unbound. Both channel families retain pending common requests across logical closure; use their documented cleanup contracts rather than assuming immediate provider teardown.

Navigation requests and lifetime

AMS.MEL.IR.Image.Submit_Navigation_Report owns the complete Navigation_Report, including all 18 covariance terms. Submission is allowed while logically Attached or Running and returns a limited Navigation_Request. Wait observes a cached terminal result. Timeout leaves the request pending; request Close abandons the public handle and is not cancellation.

Pending requests and held leases keep native provider/channel state alive independently of the public Image_Stream and Session. Parent-first logical closure is supported by retained child claims; it does not authorize new work on closed parents or promise immediate physical teardown. Metadata Close stops public consumption, not universal callback quiescence. Serialize lifecycle operations on the same owner. Read the ownership/error contracts before shutdown.

Source basis

The operation contracts are in ada/src/ams-mel-ir*.ads and ada/README.md; native behavior is in native/src/ir_stream.cpp, ir_image.cpp, ir_navigation.cpp and the corresponding channel implementations. Mock tests under ada/tests/src and native/tests establish conversions and ownership. Historical docs/task-029* reports distinguish mock-positive Track evidence from pinned-provider limitations.
