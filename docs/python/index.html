Python API

The ams_mel package provides owned Python values, explicit native owners, asynchronous requests and polling receivers over the bridge's C facade. Import public names from ams_mel. The package uses the Python standard library; importing it also requires the separately built native facade.

Start with setup and a first session, then read ownership and errors before integrating a provider. The searchable API index contains the public exports, signatures, value fields, enum members and owner methods. Implementation source views are provided for inspection and do not define an additional public API.

Implemented Python surface

Reading the reference accurately

Python currently has no safe Track or Scheduling owner, generic buffer registration or checkout API, CameraCommand submission, or LineOfSightQuaternion receiver. Names such as ChannelType.SCHEDULING and MetadataCapability.LINE_OF_SIGHT_QUATERNION belong to the advertised value vocabulary. They do not expand the implemented feature set.

Returned frames, metadata and capabilities contain Python-owned data. Native owners have separate lifecycle rules: a weak view does not keep a channel alive, closing a request does not cancel it, and closing a metadata consumer does not unregister the callback. The guides explain these distinctions and point to the corresponding method contracts.

These pages describe the checked-in Python interface and its native contracts. They do not establish hardware readiness, universal provider configuration or qualification of a particular provider. For other languages, return to the documentation portal.
