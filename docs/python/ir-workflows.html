IR workflows

Start from an open {{api:Session}} and provider-appropriate attachment values. Opening, enabling, submitting commands and registering callbacks are separate operations. Use the setup guide for facade loading and the ownership guide for synchronization, cleanup and error handling.

Discover, then attach

{{api:Session.capabilities}} returns the provider's complete advertised Control list. Each {{api:ChannelCapability}} includes channel/platform IDs, component location, channel types, image geometry, pixel format, spectral bands, metadata capabilities and navigation frames. The snapshot owns all nested data and retains no native storage.

Discovery can return an empty tuple, zero image dimensions or capability vocabulary that has no corresponding Python owner. Match the advertisement to the provider's intended configuration. Attaching remains a separate operation, and a successful attachment does not establish enablement or hardware readiness.

Once attached, obtain a complete snapshot through {{api:ChannelView.capabilities}} or the typed capability method provided by Health, Instrumentation and StackedImage. A common view is weak. Keep the typed owner alive for any operation that requires its channel.

Image acquisition and control-only attachment

ModeFactoryStart and receive
Host-memory acquisition{{api:Session.open_image_stream}} with {{api:ImageConfig}}Explicit Start enables acquisition. Receive returns owned Mono8 frames using the configured buffer pool and bounded FIFO.
Control-only Image{{api:Session.open_image_control}} with {{api:ImageControlConfig}}Returns the same ImageStream class. Start explicitly enables the channel without allocating or registering acquisition buffers. Pixel receive raises INITIALIZATION_FAILED.

Both modes support a weak common view, navigation submission and the supported metadata registrations. A control-only attachment is useful when the advertised Image channel is unconfigured for acquisition: its config needs channel ID, platform ID and component location, with no invented frame dimensions or format.

{{api:ImageStream.receive}} produces single-band Mono8 frames with copied, tightly packed pixel bytes. {{api:ImageFlip}} and {{api:ImageType}} describe provider metadata; the binding does not apply flips, offsets or optical correction to those bytes. {{api:ImageStream.counters}} reports callback activity and dropped/malformed frames, not the number of successful receive calls.

{{api:ImageStream.stop}} is terminal for the attachment. Queued frames remain drainable, followed by STREAM_STOPPED; Start cannot restart that stopped stream. Closing is a separate ownership operation. Register required metadata before Start where practical so early callbacks have a consumer.

C2 commands and their results

Create {{api:ControlChannel}} with {{api:Session.open_control_channel}}, then call {{api:ControlChannel.enable}} explicitly before command submission.

OperationInput and resultMeaning
{{api:ControlChannel.submit_mode}}{{api:ModeCommand}} → {{api:ModeRequest}}Published MFA state/mode plus complete {{api:ScanParameters}}. The binding does not infer compatible state/mode pairs or physical feasibility.
{{api:ControlChannel.submit_operate}}uint32 command ID → ModeRequestConvenience entry for the existing Operate/TaskSched profile.
{{api:ControlChannel.submit_config_set}}{{api:ConfigSetCommand}} → {{api:ReturnRequest}}Exact command ID, signed nanosecond time and opaque UTF-8 configuration text. No clock domain or provider configuration syntax is inferred.
{{api:ControlChannel.submit_bit_noop}}uint32 command ID → ReturnRequestEmpty/no-op BIT profile only. Receiving BIT advertisements does not add payload-bearing BIT execution.

For an already enabled control and a caller-supplied ConfigSetCommand, explicitly close the returned observer:

from ams_mel.ir import ConfigSetCommand, ReturnRejected


def send_configuration(control, command: ConfigSetCommand):
    request = control.submit_config_set(command)
    try:
        result = request.wait(timeout_ms=1000)
        if isinstance(result, ReturnRejected):
            print(result.code, result.description)
        else:
            print(result.value)
        return result
    finally:
        request.close()

A returned CommandReturn.FAIL is a completed result. A MEL rejection is a separate returned variant; timeout/native failure raises MelError. Closing after a timeout releases the public observer and leaves any pending provider work under the native lifetime contract.

ScanType controls are exact uint32 values, not Boolean flags. Scan parameters keep their named radians, seconds and metre fields. The wrapper validates representable values and the published enum domain; it does not plan scans, supply missing mission inputs or add a Scheduling owner.

Submit complete navigation input

{{api:ImageStream.submit_navigation_report}} accepts a complete {{api:NavigationReport}} while Image is Attached or Running, including a control-only attachment. It neither starts Image nor registers callbacks.

Input groupRequired data
Time and solutionSigned system_time_ns and a published {{api:PositionSolutionState}}. States are not an ordered quality score.
Positionlatitude_rad, longitude_rad, altitude_m, plus the independently named altitude_msl field.
Attitude and motion{{api:Euler}} attitude, {{api:AttitudeRate}} with its independent timestamp, and {{api:NorthEastDown}} speed and acceleration.
Additional orientationwander_angle_rad and magnetic_heading, without an invented convention for unspecified units.
UncertaintyAll 18 named entries in {{api:PositionVelocityCovariance}}, preserving the published field order and independent terms.

Every input is explicit. Supply actual application data and its intended conventions; do not infer a timestamp epoch, mirror covariance terms, normalize Euler components or substitute a zero-filled uncertainty matrix as an implicit default. Representable IEEE NaN, infinity and signed zero are accepted by the existing numeric contract; acceptance is not navigation-solution validation.

from ams_mel.ir import NavigationReport, NavigationRejected


def submit_navigation(image, report: NavigationReport):
    with image.submit_navigation_report(report) as request:
        result = request.wait(timeout_ms=1000)
        if isinstance(result, NavigationRejected):
            print(result.code, result.description)
        else:
            print(result.response.command_id, result.response.request_id)
        return result

{{api:NavigationCompleted}} owns a {{api:NavigationResponse}}. The same response model can arrive in ordinary Image metadata, but that callback is an independent observation. Receiving it does not replace waiting on the request, and timeout or close does not cancel the submission.

Common channel services and StackedImage

C2, Image, Health, Instrumentation and StackedImage expose channel_view(). The resulting {{api:ChannelView}} supports {{api:ChannelView.send_keepalive}}, {{api:ChannelView.submit_comms_test}} and complete capabilities. KeepAlive returns a {{api:ReturnRequest}}; CommsTest returns a {{api:CommsRequest}}. Both follow Session admission and require explicit closing.

{{api:CommsTestRequest}} contains three independent uint32 IDs: command_id, channel_id and request_id. The reply {{api:CommsTestReport}} contains only command and request IDs; the wrapper does not synthesize a reply channel ID.

{{api:Session.open_stacked_channel}} creates the StackedImage foundation owner from {{api:StackedConfig}}. Its three fields are attachment identities, with no acquisition storage or stack geometry. {{api:StackedChannel.enable}} is explicit. Complete capabilities, common services and common CommsTest callbacks are available through the implemented interfaces; stacked pixel acquisition and additional stacked metadata are not exposed.

Choose the callback receiver

Metadata is opt-in and remains independent of request futures. Each receiver consumes a native bounded FIFO. Registration may synchronously deliver events; it does not implicitly enable or start the parent channel.

RegistrationReceiver and payload
{{api:ImageStream.open_metadata}}{{api:ImageMetadataStream}} returns {{api:ImageMetadataEvent}}: BadPixelList, LineOfSightReport, LineOfSightEuler or NavigationResponse.
{{api:ControlChannel.open_metadata}}{{api:C2MetadataStream}} returns {{api:C2MetadataEvent}}: CommandStatus, BIT configuration or canonical Health BitStatus. {{api:C2MetadataStream.enable_comms_test_events}} independently adds CommsTest reports.
{{api:HealthStatusChannel.open_metadata}}{{api:HealthMetadataStream}} returns {{api:HealthMetadataEvent}}: MfaStatus, BitStatus, SubsystemStatus, DiscreteStatus, SecurityAuditRecord or MfaStatusDetailed.
{{api:InstrumentationChannel.open_metadata}}{{api:InstrumentationMetadata}} returns {{api:InstrumentationReport}}, independently of submit_level and InstrumentationRequest.
{{api:ChannelView.open_comms_metadata}}{{api:CommsMetadataStream}} returns {{api:CommsTestReport}} on Health, Image and StackedImage. C2 uses its dedicated metadata receiver; Instrumentation is not supported by this common registration.
{{api:ImageStream.open_nuc}} or {{api:HealthStatusChannel.open_nuc}}{{api:NucStream}} returns complete {{api:NucTempData}} with ordered temperature points and tagged pixel widths.
{{api:ImageStream.open_camera_response}}{{api:CameraResponseStream}} returns {{api:CameraCommandResponse}}. The safe Python package has no corresponding CameraCommand submission API.
{{api:ImageStream.open_optical_distortion_map}}{{api:OpticalDistortionMapStream}} returns a complete {{api:OpticalDistortionMap}} snapshot.

A valid native registration attempt is one-shot, including failure or partial registration. Closing a consumer does not allow registration again. Invalid local capacity is rejected before native entry. The optional NUC, CameraCommandResp and ODM registrations expose their provider Return through specialized open errors described in the error guide.

receive(timeout_ms=0) polls. Active-empty queues yield TIMEOUT; after a producer stops, queued values can drain before STREAM_STOPPED, or PROVIDER_FAILED for uncertain teardown. Overflow drops the incoming event and retains already queued events. counters() snapshots cumulative callback counts, including incoming drops and malformed/unsupported events; receive and counter reads do not reset them.

For example, this function explicitly registers ordinary Image metadata before starting an already attached Image owner. Its caller retains responsibility for closing that Image owner.

from ams_mel.common import ErrorKind, MelError
from ams_mel.ir import ImageMetadataKind


def observe_one_image_event(image):
    with image.open_metadata(queue_capacity=16) as metadata:
        image.start()
        try:
            event = metadata.receive(timeout_ms=1000)
        except MelError as error:
            if error.kind in (ErrorKind.TIMEOUT, ErrorKind.STREAM_STOPPED):
                return None
            raise
        if event.kind is ImageMetadataKind.NAVIGATION_RESPONSE:
            print(event.payload.command_id, event.payload.request_id)
        return event

Ordinary Image events enforce matching kind/payload types. BadPixelList retains reported sizes/counts independently of the ordered pixel list; coordinates are not renumbered. Line-of-sight fields retain provider values and do not infer a rate time denominator or timestamp epoch.

NUC keeps each pixel's original uint8/uint16/uint32 tag, independent of its magnitude. Temperature is in Kelvin. CameraCommandResponse keeps its full command ID, size, signed timestamp and success flag; False is a normal event. ODM retains every named dimension, range value and both ordered frd and row_col collections. Reported dimensions do not impose inferred collection lengths, and the wrapper performs no interpolation, optical correction, padding or coordinate conversion.

Health records include complete nested faults, BIT results, subsystem/software data and security variants. A {{api:SecurityAuditRecord}} contains one concrete security event, whose category belongs to its own enum; categories are not interchangeable across variants. {{api:FailureLevel}} is a set of reported categories, not a numerically ordered severity scale.

Instrumentation commands

Create {{api:InstrumentationChannel}} from its Session factory, explicitly enable it and submit {{api:InstrumentationLevelCommand}} through {{api:InstrumentationChannel.submit_level}}. The command carries an exact uint32 ID and {{api:InstrumentationPriority}} NORMAL or DEBUG. The returned {{api:InstrumentationRequest}} supports a context manager and yields {{api:InstrumentationCompleted}} or {{api:InstrumentationRejected}}.

The report's size and signed nanosecond timestamp remain uninterpreted provider data. A separately registered Instrumentation metadata report does not establish completion of the command future. The same external serialization, finite waits and independent native ownership rules apply.
