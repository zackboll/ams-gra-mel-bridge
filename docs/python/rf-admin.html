RF Admin

{{api:RFAdmin}} is an independent AdminMEL owner. It opens its own provider factory and has no IR Session parent. The safe Python RF surface consists of this owner, state-command acceptance and shutdown; RF data, product reception, virtual apertures and job interfaces are not exposed.

Open with provider configuration

First set up the native facade as described in getting started. Then pass the provider library and its documented UTF-8 configuration to {{api:RFAdmin.open}}. The configuration text is provider-defined. The bridge invokes createAdminMEL once; it does not supply a universal grammar.

from ams_mel import MFAState, RFAdmin


def request_rf_state(provider_library, configuration,
                     desired_state: MFAState):
    with RFAdmin.open(provider_library, configuration) as admin:
        return admin.command_state(desired_state)

The example takes the desired state from its caller. Opening or entering the context does not choose a state or infer a provider transition sequence.

Interpret state-command acceptance

{{api:RFAdmin.command_state}} accepts {{api:MFAState}} or an integer in the published range 0..14; Boolean values are rejected. The method returns True if the provider accepts the request and False for normal refusal. A successful call does not prove that hardware reached the requested state, that RF emission occurred or that other provider interfaces are available.

Missing interfaces, provider exceptions, invalid input and malformed native results raise {{api:MelError}}. Inspect its structured {{api:ErrorKind}} and diagnostics. The binding has no implicit transition table, background polling, retry loop or asynchronous RF request owner. An application's next state request must follow its provider's actual contract.

{{api:RFAdmin.is_open}} describes the local public handle. It does not report provider health or the current hardware state.

Shutdown and synchronization

Externally serialize every operation and Close on one RFAdmin owner. The GIL does not provide the required native ownership synchronization. The owner retains no Python parent; native code manages provider-library lifetime.

{{api:RFAdmin.close}} consumes the public handle and attempts shutdown once, including when shutdown reports failure. Repeated close is harmless and does not repeat uncertain shutdown. Explicit close and normal context exit report failures; exceptional context exit preserves the body exception, and finalization is non-raising. A shutdown exception can require permanent native graph retention, so local closure is not proof of provider unload.

For the shared error model, finite diagnostic behavior and context-manager rules, see ownership and errors.
